**Tier** T2 · **Est** 0.5 day · **Depends on** A3, P4 · **Phase** 7 Producer

With P4 itself unlikely to land before submission, the honest status is: **fold it, or cut it.** This brief exists so the idea is not lost, not because it should be built this week.

## Goal

After the whistle, a report appears without anyone asking: what was said, what was checked, what held up.

## Why "unasked" is the whole point

A report you have to request is a feature. A report that is simply there when the match ends is a **posture** — it says the system expects to be audited. That is the producer-trust story, and it costs almost nothing because every input already exists as data: `Moment`, `Claim`, `Verification`, `Rendition`, and `ProducerAction` if P2 landed.

## What to build

- `audit.record()` currently *"keeps nothing yet"* — give it somewhere to keep things.
- A report per match: moments fired, claims made, verdicts, suppressed renditions with their reasons, producer interventions.
- Generated at `period_end` of the final period, not on request.

## ⚠️ O4 is open and this is what it blocks

**O4 · Audit as an Azure Function or in-process.** Under D23 — one container, no Service Bus on the path — in-process is the obvious answer, and a separate Function would mean re-introducing the trigger plumbing D23 removed. That reasoning probably resolves O4 by implication, but it is Kehinde's to settle rather than mine to assume.

## Acceptance criteria

- [ ] A report exists after the final whistle with no request made
- [ ] It covers moments, claims, verdicts, suppressed renditions with reasons, and producer actions
- [ ] Every figure in it traces to a stored row; nothing is recomputed for the report
- [ ] It is generated once, not per viewer
- [ ] Nobody waits for it — the report never blocks delivery or the final cards

## Do not

- Do not make it a request endpoint. Unasked is the feature.
- Do not recompute anything. The report reads the record.
- Do not block the match on it.
