# A5 · Degradation ladder with automatic fallback L0→L4

**Tier** T1 · **Est** 0.5 day · **Depends on** A4, L3 · **Phase** 6 Agents
**📝 Walkthrough required** (D29) — `docs/walkthroughs/A5.md`.

## ⚠️ Its dependency on A4 is probably wrong — ask

A5 falls back **to** things, and everything it falls back to is already built:

```
L3  score + clock only          -> S3, done
L2  deterministic events        -> M1a/M1b, done
L1  template prose, no LLM      -> L7 claims + L3 renditions, done
L0  full agent generation       -> A2 / A4
```

So A5 needs **something to fall back from**, which is A4, the generated prose — and optionally A2's extra claims going quiet.

**D35 shrank this ticket.** The claim path no longer swaps: L7 is always the claim source and A2 only adds to it, so there is no claim-side fallback to build. What remains is the prose rung, A4 → L3, plus noticing when A2 has stopped contributing. That is most of a day's work removed.

**This is the cheapest high-value ticket in Phase 6**, and it is cheap precisely because the build order rule in `CLAUDE.md` was followed: *"the agents are an upgrade on working software, never a dependency."* A5 is where that pays out.

## Goal

When a model is slow, down or returns nonsense, the product drops a rung **and says so**, automatically.

## What to build

- A ladder with one place that knows the current rung, and one rule for dropping: model timeout, queue pressure, malformed output, or a verification failure rate above a bar.
- **Falling back is not failing.** At L1 the viewer gets template prose off L7's claims — a complete, honest card. Nothing goes blank.
- `Rendition.suppression_reason = degraded` when the ladder falls **below** L1, which is what the data model reserves that value for. Above L1 the card is rendered, not suppressed.
- Say so, visibly: the producer monitor (P1) and the deployed page should be able to show the current rung. A silent degradation is a product that looks broken for no stated reason.
- Recovery: the ladder climbs back when the model returns, and it does not oscillate card by card.

## Acceptance criteria

- [ ] **Kill the model and the product still works.** With no model available at all, cards still arrive carrying L7's claims and L3's prose. This is the criterion the whole build order exists to make true, and under D35 it holds by construction on the claim side — assert it anyway, because "by construction" is a thing that stops being true
- [ ] A model timeout drops exactly one rung, not straight to L3
- [ ] Malformed model output drops a rung rather than emitting a repaired card
- [ ] A rendition produced below L1 carries `suppression_reason = degraded`; one produced at L1 does not
- [ ] The current rung is observable — in a trace attribute and on the producer view
- [ ] The ladder recovers when the model returns, and does not flap between rungs on alternate cards
- [ ] A forced degradation mid-match is visible in the demo and does not interrupt the clock or drop a queued card

## Definition of done

Criteria pass, green, status updated, and `docs/walkthroughs/A5.md` written.

**Record one thing for the pitch:** a screenshot or short clip of the model being killed mid-match while the three panels keep working. That is the most reassuring forty seconds available to a platform buyer, and it is the demonstration of *"the agents are an upgrade on working software, never a dependency."*

## Do not

- Do not blank a card, ever. Drop a rung.
- Do not degrade silently.
- Do not let a degraded card assert anything its claims do not support — the rung changes the prose, never the evidence.
