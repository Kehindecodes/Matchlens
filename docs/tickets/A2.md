# A2 · Explainer agent emitting structured Claims

**Tier** T1 · **Est** 2 days · **Depends on** A1, M1b · **Phase** 6 Agents
**📝 Walkthrough required** (D29) — `docs/walkthroughs/A2.md`. One of the two deepest: this is the agent-orchestration lesson.

## ⚠️ L7 changed what this ticket is

When A2 was written, nothing produced claims. **L7 now does** — D30's eight metrics, built by rule from the frozen log, with no model. Cards already say *why*.

So A2 is no longer "make claims exist". It is **a model proposing *additional* claims in the same `Claim` schema and the same closed `Metric` vocabulary** — on top of L7's, never instead of them (**D35**).

**Additive, not primary.** A claim is the audit substrate: what A3 verifies and what the evidence drawer shows. If A2 owned the claim path, a model failure would remove the *evidence* rather than just the wording, and the product would need a swap and a trigger to detect it. Additive means A2 contributing nothing is simply fewer claims, with no fallback path to get wrong.

That reframing is the whole ticket. Get it wrong and A2 becomes a second, incompatible claim source that cards depend on.

## What A2 actually adds over L7

L7 applies D30's per-moment-type table: a goal always gets `goals`, `build_up_passes`, `shot_quality`. Fixed, correct, and uniform.

A2 brings **judgement inside a closed vocabulary**:

- which of the eight metrics are worth claiming *for this particular moment*
- which comparison to draw — D30 allows both *"the same team earlier"* and *"the opponent over the same window"*, and choosing between them is editorial
- the interpretive `threshold` and the wording band it implies

**It must not invent a metric.** `Metric` is a closed enum (D30, D14) and A3 recomputes every value from cited rows. A ninth metric is an unverifiable claim, and invariant 5 drops it — so a model that strays produces nothing, not something new.

## What to build

- `explanation/` gains a model path alongside L7's builder, behind the same `explain()` signature.
- **Structured output, validated at the boundary.** The model's response is parsed into `Claim` objects and the pydantic validators are the gate — `_operands_match_the_claim_type` and `_only_an_interpretive_claim_is_backed` already encode D21's arity rule and the interpretive requirement. A non-conforming response is a **failure to be reported, not a response to repair**.
- `model` and `model_version` on every claim (invariant 7).
- Microsoft Agent Framework, **pinned to an exact version on day one**. Foundry SDK for the model.
- A claim with nothing citable is **dropped at source**, not softened or hedged (invariant 5).
- The frozen log comes from A1 and nothing else. The agent never receives a `Frame` (invariant 1).

## ⚠️ Latency: the offset is your budget (D36)

The first wiring measured ~20 s a call. **Do not try to make the pipeline wait for it.**

- A2's deadline is **per moment and set by policy**, not per viewer (D36, amended 25 Oct). The release queue gives the slow path slack — a card is not released until the viewer's clock reaches it — but viewers hold different offsets, and a deadline derived from any one of them would make the same moment produce richer cards for later viewers. One deadline per moment, release at `max(viewer's due time, deadline)`, same content for everyone.
- **Target single-digit seconds.** The budget absorbs a fast call; it does not rescue a slow one. At a 10 s offset a 20 s call misses every time.
- Miss the deadline and the card ships on L7's claims. Under D35 that is a complete card, so a miss is cheap.
- **Pass A2 a moment-scoped slice, not the whole `frozen_log`.** At minute 80 that log is ~1,800 events and it is the likeliest cause of the 20 s. A2 needs the moment, its trigger readings and events, L7's existing claims, and the possession around a shot.
- **One structured-output call**, not a multi-turn agent loop with reflection.
- Warm the model at container boot so the first viewer does not pay cold start twice.
- **The 25× demo cannot meet the budget** — 45 s of offset passes in 1.8 s of wall time — so the replay serves pre-computed claims over the demo seed (D36). Build the cache path with the live path.

## Acceptance criteria

- [x] **Every claim A2 emits validates as a `Claim`** and uses only D30's eight metrics. A test with a deliberately odd moment asserts no invented metric escapes
- [x] **Every value A2 claims recomputes from its cited evidence.** This is the contract with A3; assert it here rather than discovering it there
- [x] A model response that does not conform produces **no claims and a logged failure**, never a partially repaired claim
- [x] **A2 contributing zero claims changes nothing else.** With no model available, cards carry L7's claims and read correctly — and there is no swap, trigger or fallback path to exercise, because there is nothing to fall back *to* (D35)
- [x] Comparative claims carry a real second operand with its own window and evidence (D21), not a restated first
- [x] Interpretive claims carry a **signed** `threshold` matching the wording band (D30, amended by Q26 3a)
- [x] The agent never sees past the moment's clock — A1's poisoned-log test covers the path A2 uses
- [x] `model` and `model_version` are set and asserted

**Outcome (24 Oct).** All criteria pass against scripted models; no live model has been called (Q33: B). Under Q32: A, "every value recomputes" is asserted for a model that follows the instructions; a model whose numbers are wrong is A3's to reject, and until A3 lands no card shows an A2 claim (`test_no_card_depends_on_a2[Liar]`).

- [x] A2 is given a moment-scoped input, and a test asserts the whole match log is **not** in the prompt
- [x] A call exceeding its deadline is abandoned, the card ships on L7's claims, and the miss is recorded rather than silent
- [x] One model round trip per moment — assert the call count, so a framework loop cannot creep back in
- [x] Claims cached over the demo seed match what the live path produces for the same moments (invariant 9 makes this checkable)

**Outcome, D36 (25 Oct).** A2's claims are on cards (option B, replacing Q32: A and Q34: A; Q37). Only goals and chances call the model; their cards wait up to 5 s from the moment firing, then ship on L7's claims and whichever of A2's passed A3. The input is a slice: about 1,600 tokens at minute 82, against about 6,000 before. The cache is keyed on the exact instructions and prompt. Since a real model's output varies, "matches what the live path produces" is checked as *the cache answers exactly the prompt the live path sends*: `test_the_cache_serves_exactly_what_the_live_path_is_asked`. The live model's median is **12 s** even with reasoning effort low and the smaller input, so live calls miss the 5 s deadline. The latency target is not met; the demo serves from the cache.

## Definition of done

Criteria pass, green, status updated, and `docs/walkthroughs/A2.md` written — what the prompt had to constrain, what the model got wrong before it got it right, and why the schema is the contract rather than the prompt.

## Do not

- Do not emit prose. The explainer emits claims; words are Rendering's (A4).
- Do not add a metric, a claim type, or a field.
- Do not repair a malformed model response into something that validates. A claim that had to be fixed up was not the model's claim.
- **Do not replace L7, and do not let any card depend on A2 having run** (D35). Its claims are additions to a complete set, not a set of their own.
