# P1 · Producer view: all lenses live, idle vs broken

**Tier** T2 · **Est** 1 day · **Depends on** L4 · **Phase** 7 Producer

## Goal

One screen showing every lens at once, where a lens showing nothing is distinguishable from a lens that has failed.

## Why it is possible at all

**Invariant 11 is what makes this buildable:** *"a suppressed rendition is a record, not an absence."* A lens that deliberately says nothing has a `Rendition` with `suppressed=true` and a `suppression_reason`. A lens that is broken has **no rendition at all**.

Without stored silence those two states look identical, and a producer watching a quiet panel could not tell whether the system was working. That is the whole reason D14 exists.

## Build once

The backlog is explicit: *"largely the same component as the J3 demo view. Build once."* L4 already renders three panels on one clock. The marginal work here is **the internals a viewer must never see**:

- per lens: the last card, the current card count against `max_cards_per_10min`
- **why a lens is quiet** — the `suppression_reason` in words
- the importance score of the moment that did or did not clear the threshold
- the current degradation rung (A5), so a degraded run is visible rather than inferred
- a lens with no rendition flagged as **broken**, not quiet

## Acceptance criteria

- [x] All lenses on one screen, on one clock
- [x] A suppressed lens shows its reason; a lens with no rendition is flagged as broken. **Construct both and assert they render differently** — this is the ticket's only real requirement
  - `test_a_lens_that_chose_silence_and_a_lens_with_no_rendition_render_differently` and `test_the_page_styles_a_quiet_lens_and_a_broken_one_differently`
- [x] Importance scores and rate-limit state visible per lens
- [x] The degradation rung is shown when below L0
  - A5 landed first, so this is its strip and its `ladder` event, shared through `panel.js`. It shows on every rung, which includes below L0
- [x] None of this leaks onto the viewer pages
- [x] Shares components with L4 rather than duplicating them
- [x] No new dependency

## Do not

- Do not build a second panel implementation. If L4's component cannot show internals, extend it.
- Do not show internals to viewers.
- Do not let the producer view recompute anything.

## As built (Q42: 1A, 2A, 3A, 4B)

- **Where it lives.** `/producer`, `web/producer.html` with `producer.js` and `producer.css`. It is the demo view's panels (`panel.js`, `app.js`, unchanged but for `app.js` handing back the mounted panels) with one block added per panel, fed by `GET /producer/stream`: a fourth `EventSource` beside the three sessions (Q24: A).
- **What crosses the bus.** `MomentOutcome` and `LensOutcome` (`matchlens/rendering/outcomes.py`), sent beside `Card`, never stored, never sent to a viewer. `Pipeline` takes a `report` callback and calls it once per moment with every lens's rendition (suppressed or not), the importance the lens judged and its rate-limit count.
- **Quiet, alarm, broken.** A lens that chose silence is **Quiet by choice** (out of scope, muted, claims filtered, below threshold, rate limited). `verification_failed` is **Quiet, but not by choice**, an alarm (DATA-MODEL calls it one). A lens with no rendition at all, or whose rendition is `degraded`, is **Broken**. A5 made a Rendering failure a stored `degraded` rendition, so "no rendition at all" is now only a moment that failed outside Rendering; both read as broken because neither is a choice. One dict, `STATE_OF_REASON` in `matchlens/delivery/producer.py`, is the whole mapping.
- **Nothing vanishes.** A moment that fails outside Rendering on the editorial thread used to disappear into a future nobody read. `_guarded` logs it, reports it failed (every lens then has no rendition), and re-raises, so `drain()` behaves as before. Viewers are unchanged: no card from that moment.
- **Who can reach it (4B).** `MATCHLENS_PRODUCER_VIEW`, off by default and `true` in `infra/main.bicep`. Off, `/producer`, its stream and its three static files are 404, and no viewer page links to it or mentions it (a test reads every viewer asset).
- **Not done here.** The sync path (no model) still lets an exception in `_editorial` end the feed task, as before. It is not silent, but it is not reported to the producer view either; only the editor-thread path is guarded.
