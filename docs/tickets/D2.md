# D2 · Two sessions on different offsets, both correct

**Tier** T1 · **Est** 0.5 day · **Depends on** D1 · **Phase** 5 Delivery
**📝 Walkthrough required** (D29) — may be folded into `docs/walkthroughs/D1.md`.

## Goal

A viewer 45 seconds behind the action and a viewer 5 seconds behind each get the same card **at the right point in their own stream.**

## It is a test, not a feature

Nothing ships from this ticket. It is the proof that D1 is real, and it is the clearest possible demonstration of the one thing no competitor does per viewer — so it earns its row by being *demonstrable*, not by adding behaviour.

**Cut ladder rung 4 offers folding it into D1** (*"both tests rather than features, −1, free, take it now"*). That rung has never been taken. With two build days left it probably should be: the assertions below belong in D1's test file either way, and the only thing lost is a separate row in the backlog.

## What to build

- Two sessions on the same lens, offsets of 45s and 5s, one match replay.
- Assert each receives every card, in the same order, at the correct point relative to **its own** viewer position.
- A visible version for the demo if it is cheap: two panels side by side on different offsets, the same goal card landing at different wall-clock moments. That shot explains per-viewer delivery faster than any sentence in the pitch.

## Acceptance criteria

- [ ] Both sessions receive the identical set of cards, in the identical order
- [ ] The 5s viewer receives each card **earlier in wall time** than the 45s viewer, by the offset difference
- [ ] Neither receives a card before their own `match_clock_now − stream_offset_ms` reaches its `display_at_clock`
- [ ] Changing one session's offset mid-match does not disturb the other's queue
- [ ] An offset of 0 behaves — it is the degenerate case and the one most likely to be special-cased wrongly

## Definition of done

Criteria pass, green, status updated. If folded into D1, say so in the status rather than leaving the row `todo`.

## Do not

- Do not add delivery behaviour here. If a criterion cannot be met without changing `release.py`, that is a D1 bug — fix it there.
