# S2 · Ingest, and the frame access boundary

**Tier** T1 · **Est** 1 day · **Depends on** F3, S1 · **Phase** 1 Walking skeleton

## Goal

Accept the source stream, keep a rolling window of frames in memory, persist events, and **make it structurally impossible for anything downstream of Understanding to read a frame**.

## The boundary is the point of this ticket

> Agents never read `Frame`. They read events, possessions, signal readings and above. Frames exist only for detectors. **Enforce this in the data access layer, not by convention.**

This is invariant 1 in `CLAUDE.md`, and it is the one most likely to erode quietly. A code comment will not hold. A failing test will.

Why it matters: frames are tens of thousands of positional rows. An LLM handed frames will hallucinate patterns from them, and there is no way to verify a claim whose evidence is "I looked at the positions". Every claim must cite an `event_id`, `run_id` or `reading_id` — things with IDs and recomputable values.

## What to build

- `matchlens/ingest/` — `accept(item)` routing frames to the window and events to storage.
- A frame window: a bounded in-memory structure keyed by `clock_ms`, holding the last N minutes. **Never a row per frame in a database** (see the storage tiers table).
  - At 2 Hz the whole match is ~10,800 frames and a plain list is fine. At 10 Hz, use a ring buffer. Size it from `settings`.
- `frame_window(clock_ms, span_ms) -> list[Frame]` for Understanding.
- Event persistence behind a repository interface. **O1 is unresolved** — do not pick a database. Write an in-memory implementation behind the interface and leave the real one for S5.
- **The boundary mechanism.** Suggested shape, but the design is yours:
  - Frames are reachable only through an `understanding`-scoped accessor, not from the general repository.
  - The general record accessor that Explanation and Verification use has no frame method at all.
  - A test that imports the agent-facing accessor and asserts it exposes no way to reach `Frame` — by attribute inspection, not by trusting the author.

## Acceptance criteria

- [ ] **The roster loads before the stream opens.** `Team` and `Player` arrive as a pre-match setup message, and Ingest **refuses** frames or events until they are present. A test asserts that an event arriving first raises rather than creating a dangling player reference (D16)
- [ ] Frames and events from F3's stream are accepted in `seq` order
- [ ] `frame_window` returns only frames inside the requested span
- [ ] The window is bounded — a test runs a full match and asserts memory does not grow unboundedly
- [ ] Events are retrievable by clock range through a repository interface
- [ ] **A test fails if an agent-facing accessor can reach `Frame`.** This is the acceptance criterion that matters; write it first.
- [ ] A test asserts `frozen_log(clock_ms)` returns nothing with `clock_ms` greater than the argument — the groundwork A1 builds on

## Definition of done

Criteria pass, green, status updated. The boundary test is named something obvious like `test_agents_cannot_reach_frames` so nobody deletes it by accident.

## Do not

- Do not choose a database. O1 is Kehinde's call and it blocks nothing until S5.
- Do not derive anything. Possession, shot quality and signals are U1–U3.
- Do not let the window write to storage. Frames may optionally become one compressed blob per match later; that is not this ticket.
