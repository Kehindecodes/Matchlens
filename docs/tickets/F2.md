# F2 · Match-record models

**Tier** T1 · **Est** 1 day · **Depends on** F1 · **Phase** 0 Foundation
**Stories** none directly. Everything downstream types against these.

## Goal

Pydantic models for group A of the data model — `Match`, `Team`, `Player`, `Frame`, `Event` — complete, typed, and round-tripping through JSON.

Read `docs/DATA-MODEL.md` section A **and `docs/RELATIONSHIPS.md` section A** first. Every attribute must be present, and the cardinalities are validators, not comments.

## What to build

- `matchlens/models/match_record.py` (or a small package if it reads better — your call).
- All five entities with every documented attribute.
- The enums for group A, **named and valued in `docs/DATA-MODEL.md` under "Enumerated types"**: `Phase`, `Action`, `Outcome`, `BodyPart`. Do not invent values — the list is declared. Closed sets as enums, not strings, because the verifier's checks depend on these being exact and a typo in a string field fails silently.
- The `RefKind` enum and the `Ref` type, since three polymorphic relationships depend on them. Put these somewhere shared — later groups use them too.
- JSON round-trip: `Model.model_validate_json(m.model_dump_json()) == m`.

## Things that are easy to get wrong

- **`Frame.players` is a positional array** — `[player_id, x, y, speed]`, not a list of objects. At thousands of frames per match the key names roughly double the payload. Type it as such and add a tiny accessor if readability suffers.
- **`seq` is the ordering key for the whole system.** Monotonic across both frames and events, so an event and the frame it aligns to can be ordered against each other.
- **`clock_ms` is always milliseconds from kickoff**, as an int. Not seconds, not a timedelta, not wall clock.
- **`attack_direction_by_period` is applied at read time, never at write time.** Store raw coordinates. A helper that normalises for a team and period belongs here, but it must not mutate stored values.
- **`Match` has exactly 2 teams, not many.** Validate it. Every signal is per-team and a third team silently breaks every baseline.
- **`Frame.players` is not always 22.** It shrinks after a sending-off. Do not hardcode the length.
- **`Event.frame_ref` is mandatory, exactly one frame.** Positional context must always be recoverable.
- **`Player.off_clock_ms` nullable means they finished the match.** The verifier's entity check reads `on_clock_ms`/`off_clock_ms` to decide whether a named player was on the pitch at a claim's clock. Get the boundary semantics explicit: is a claim at exactly `off_clock_ms` valid? Pick inclusive-start, exclusive-end and write it in the docstring.
