# U3 · Five signal functions

**Tier** T1 · **Est** 2 days · **Depends on** U1, U2 · **Phase** 2 Understanding

## Goal

One function per `Signal`, each computing that signal's value for one team over a window, on a rolling cadence.

## ⚠️ Ask before starting — two things

**1. O5 is unresolved and overdue (it was due 16 Oct): three signals or five.** Do not pick.

There is a consequence of O5 that is not in the one-line spec and should be on the table before it is answered: **`line_height` is the only signal that reads the frame window.** If O5 drops it, nothing anywhere downstream reads a `Frame`, and `FrameAccess` plus F3's frame generation have no consumer at all. The boundary test still demonstrates invariant 1 and is still worth keeping, but the window becomes dead weight. That makes O5 an architecture decision, not only a scope cut.

**2. The one-liner says "emitting SignalReading", and this ticket cannot do that.** `SignalReading` is frozen with `baseline`, `z_match` and `z_prior` required, and those are U4 — which is 🧑 reserved. So U3 stops at values, `n` and `confidence`, and U4 assembles the row. Building complete readings here would either write U4 or invert the dependency. Flagged rather than assumed: if Kehinde wants U3 to emit whole rows, this ticket has to come after U4.

## ⚠️ The endpoint trap — read this before writing the window code

The two APIs this ticket reads from use **opposite interval conventions**:

| API | Interval |
|---|---|
| `RecordReader.events_between(from, to)` | **`[from, to)`** — inclusive start, exclusive end |
| `FrameAccess.frame_window(clock_ms, span_ms)` | **`(clock − span, clock]`** — exclusive start, inclusive end |

One nominal window handed to both includes different boundary items. The failure is quiet: possession share comes out slightly wrong at every window edge, every signal is affected a little, and nothing crashes. Pick one convention for the signal window, convert explicitly at each call site, and **put a test on the conversion** so the next person does not have to rediscover this.

Second edge on the same theme: `frame_window` **refuses** `span_ms > retention_ms` rather than truncating. With `settings.signal_window_ms` at 300 s, the `FrameWindow` retention must cover the clamped window or `line_height` raises at runtime. Assert the relationship at startup rather than finding it mid-match.

## What to build

`matchlens/understanding/signals.py`, one function per `Signal` member, all with the same signature, returning the value in the signal's own units with those units in the docstring:

- **`territory`** — share of in-play possession time or events in the opponent's third, from U1's `start_zone` / `end_zone`
- **`possession_control`** — possession share over the window, from U1's records
- **`pressing_intensity`** — PPDA: opponent passes per defensive action in the opponent's own two-thirds. Call it `pressing_intensity`, never PPDA in a user-facing string
- **`chance_quality`** — U2's shot values aggregated over the window
- **`line_height`** — mean distance of the defensive line from its own goal, from the frame window via `FrameAccess` only

Also:
- **`n` and `confidence`.** The window's sample count, and a confidence that falls as `n` falls. Thin windows must be visibly thin, because this is what stops a two-event window reading as a tactical shift.
- The **rolling cadence** — how often a reading is produced. One decision, in config, not per signal.
- The **clamped window** (D15): `window_start = max(clock − settings.signal_window_ms, epoch.start_clock_ms)`. The effective width goes on the reading as `window_ms`, which is why the field exists.
- `calltrace.entered("Understanding")`.

## Acceptance criteria

- [ ] One function per `Signal` member being built, identical signatures, units documented
- [ ] **Stopped time is excluded** from the four event-derived signals. A test over a window containing a long stoppage gets the same answer as the in-play-only computation
- [ ] The window conversion test above: one nominal window, both APIs, boundary items accounted for deliberately
- [ ] `line_height` reads frames only through `FrameAccess`, and **no reading carries a frame id or a frame-derived field other than its value**. Frames stop at Understanding (invariant 1, and the boundary in `ARCHITECTURE.md`)
- [ ] A span exceeding frame retention fails loudly at startup, not mid-match
- [ ] `confidence` is materially lower on a 2-event window than on a full one — assert the direction, not a magnitude
- [ ] `window_ms` on the output equals the clamped width, and equals the nominal width only when the epoch is older than the window
- [ ] Deterministic on a fixed seed
- [ ] Each signal reads sensibly on at least two archetypes — a signal that a coin flip could satisfy is not calibrated. R2 provides the archetypes; if only one exists, say so rather than asserting against one match

## Definition of done

Criteria pass, green, status updated. Note in `docs/QUESTIONS.md` anything the calibration forced you to assume.

## Do not

- Do not compute baselines, `z_match` or `z_prior`. **U4 is 🧑 reserved** — leave those absent and say so.
- Do not decide what is interesting. No thresholds, no importance, no cooldown. That is M1.
- Do not let `chance_quality` be called xG anywhere.
- Do not add a sixth signal, however tempting. D10 says these are an orthogonal basis, not a bag of detectors.
