# L2 · Selection: scope dispatch, threshold, rate limit

**Tier** T1 · **Est** 1.5 days · **Depends on** M1b, L1 · **Phase** 4 Lenses ⭐

## Goal

Real `select()`, replacing the stub that returns every claim. For each lens: dispatch on `scope`, apply `importance_threshold` and `max_cards_per_10min`, filter by `allowed_claim_types`.

## ⚠️ The stub's signature cannot express the most important outcome

`select(moment, claims, lens) -> list[Claim]` can return an empty list, but it **cannot say why it is empty** — and the why is the product. `SuppressionReason` is ordered and the first match wins (D14), and four of its seven values are Selection's own knowledge:

| Reason | Owner |
|---|---|
| `out_of_scope` | **Selection** |
| `muted` | Control |
| `degraded` | the ladder (A5) |
| `verification_failed` | Verification |
| `claims_filtered_out` | **Selection** |
| `below_threshold` | **Selection** |
| `rate_limited` | **Selection** |

Rendering cannot infer which applies — it does not know the threshold or the rate-limit state. So Selection has to return the claims **and** the reason when there are none. Signatures are yours to choose (CLAUDE.md), but choosing one that drops the reason loses invariant 11.

## Scope is two code paths, not one filter (D2)

Dispatch off `scope`. Do not write one filter taking different arguments:

- **`match`** — no subject logic at all.
- **`team`** — a **reweight plus a framing transform**, not a filter. It drops almost nothing by subject, because *a moment about the opponent is maximally relevant to a supporter*. It boosts moments affecting the result and drops neutral tactical curiosities. The framing half is L3/L6; the reweight is here.
- **`player`** — a hard subject filter. Deferred (D1), so do not build it, but dispatch to a clear `NotImplementedError` rather than falling through to the match path.

The reweight is the counterintuitive part and the one most likely to be built wrong: **team scope keeps opponent moments.** A filter that drops them is a player-scope mechanism applied to the wrong axis.

## What to build

- Real `select()` in `matchlens/selection/__init__.py`. **No model call, ever** (D17) — every model call lives in Rendering, which is what makes a model outage unable to change which claims a lens shows.
- Order the steps and document the order: scope dispatch → importance threshold → claim-type filter → rate limit. The order decides which `SuppressionReason` wins, so it is behaviour, not style.
- **`max_cards_per_10min` needs per-lens state across moments** — a rolling count on the match clock, not wall clock. Same family of streaming state as M1a's histories, and it must reset per match so two matches cannot rate-limit each other.
- `allowed_claim_types` filtering, which is how the casual lens loses comparative claims carrying raw numbers.

## Acceptance criteria

- [ ] **V3 holds:** a moment above the analyst threshold and below the casual one yields claims for analyst and a suppressed outcome for casual, carrying `below_threshold`
- [ ] A suppressed outcome always carries exactly one reason, and it is the first applicable one in the declared order (D14)
- [ ] **Team scope keeps opponent moments.** Construct a moment whose subject is the opponent and assert the team lens keeps it, reweighted. This is the test that catches team scope built as a filter
- [ ] Team scope drops a neutral tactical curiosity that the analyst lens keeps
- [ ] Rate limiting is on the match clock and resets per match; two matches in one process do not interfere
- [ ] A lens at `max_cards_per_10min` suppresses with `rate_limited`, not `below_threshold`, even when the moment also clears the threshold — assert the precedence directly
- [ ] `player` scope raises rather than silently behaving like `match`
- [ ] **No model call and no import of anything agentic** in `matchlens/selection/`. A test on the import graph, not a comment
- [ ] Deterministic: same moments and lenses, same selections
- [ ] No lens id string literal anywhere in the module (invariant 10)

## Definition of done

Criteria pass, green, status updated.

## Do not

- Do not write text. Selection chooses claims; Rendering writes words (D17).
- Do not read frames, and do not read `Match.archetype_id` (D25).
- Do not implement the partisan framing — that is L6, and it lives in Rendering.
- Do not let an empty selection reach Rendering without a reason.
