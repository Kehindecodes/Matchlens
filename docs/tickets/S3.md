# S3 · SSE endpoint, ViewerSession, minimal page

**Tier** T1 · **Est** 1 day · **Depends on** S1 · **Phase** 1 Walking skeleton
**Stories** V1 (the choice persists if the viewer reloads mid-match)

## Goal

A FastAPI app serving a plain HTML page that shows a ticking match clock and the score, fed over Server-Sent Events, with a `ViewerSession` that survives a reload.

## Why SSE and not WebSocket

Nothing the viewer sends needs a duplex connection — lens switches, position reports and playback controls are all low-frequency POSTs. SSE gives reconnection and resumption free, and `Last-Event-ID` maps directly onto the release buffer that D1 builds. Do not substitute.

## What to build

- `apps/delivery.py` — the FastAPI entrypoint for the delivery container.
- `GET /` serving `web/index.html`. Plain HTML and JS, **no framework and no build step.**
- `GET /stream?session_id=...` — the SSE endpoint. Correct headers (`text/event-stream`, no buffering), a keepalive comment every 15–30 seconds or intermediaries will drop idle connections, and an `id:` on every event so `Last-Event-ID` works.
- `POST /session` creating a `ViewerSession`, returning its `session_id`.
- `ViewerSession` model: `session_id`, `lens_id`, `language`, `joined_at`, `last_seen_clock`, `stream_offset_ms`, `focus_team`. Default `lens_id` to `settings.default_lens_id` — **whole match at casual depth** (V1).
- Session persistence good enough to survive a page reload. In-process is fine for now; it moves to a key-value store only if we ever scale delivery, which we will not in v1.
- The page: score, clock, and a reconnect that resumes rather than restarting.

## Acceptance criteria

- [ ] Opening the page shows a clock that ticks and a score
- [ ] Reloading the page keeps the same session and the same lens (V1)
- [ ] The SSE stream survives a dropped connection and resumes from `Last-Event-ID` without replaying everything
- [ ] A keepalive is sent on an idle stream — a test asserts something arrives within 30 seconds of silence
- [ ] A session created with no lens gets whole-match-casual
- [ ] Two browser tabs get two independent sessions

## Definition of done

Criteria pass, green, status updated.

## Do not

- Do not implement the release queue or stream offset. The field exists on the model; the behaviour is D1. For now, send whatever arrives.
- Do not build three panels. That is L4. One lens is enough for the skeleton.
- Do not add a frontend framework, a bundler, or a CSS library.
