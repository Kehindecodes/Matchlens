# S6 · App Insights, one trace per moment

**Tier** T2 · **Est** 0.5 day · **Depends on** S5 · **Phase** 1 Walking skeleton

## Goal

One distributed trace per moment, spanning spotter → explainer → verifier → personalizer, with `moment_id` as a trace attribute and timings on each span.

## Why this is the best-value item on the infrastructure list

It does double duty. It is operational excellence for the Cloud Native prize, and it is **visible proof of agent handoffs** for the Multi-Agent prize.

A screenshot of that waterfall is evidence of orchestration that no amount of prose achieves: it shows the agents are genuinely separate, genuinely sequential, and genuinely handing work to each other. Prose claiming four agents is a claim; a trace showing four spans is a fact.

## What to build

- Application Insights, wired into both container apps.
- OpenTelemetry instrumentation with a span per pipeline stage.
- A trace started at Spotting when a moment is created, propagated through Explanation, Verification and Personalization.
- `moment_id` as a span attribute on every span in the trace, so a trace can be found from a card.
- `latency_ms` on `Verification` populated from the real span duration rather than a separate measurement.
- Useful attributes: `lens_id` on personalization spans, `verdict` and `claim_id` on verification spans, `model` and `model_version` where an LLM is called.

## Acceptance criteria

- [ ] One moment produces one trace with at least four spans in the right order
- [ ] Searching App Insights by `moment_id` finds the trace
- [ ] Each span carries a duration, and the sum is close to the observed end-to-end latency
- [ ] `Verification.latency_ms` matches its span duration
- [ ] The trace survives the Service Bus hop between the two container apps — this is the part that usually breaks, because context does not propagate through a broker without explicit work

## Definition of done

Criteria pass, green, status updated. **Capture the waterfall screenshot** and put it in `docs/evidence/`. You will want it for the pitch and it is easier to grab now than to recreate later.

## Do not

- Do not add custom metrics or dashboards. Traces are the valuable part; dashboards are time.
- Do not instrument the simulator or the frame window. High-volume, low-value, and it will drown the useful traces.
- Do not log claim text or rendition bodies as span attributes. Spans are not a content store.
