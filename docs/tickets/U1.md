# U1 · Possession sequencing from events

**Tier** T1 · **Est** 0.5 day · **Depends on** S2 · **Phase** 2 Understanding

## Goal

Turn the event log into `Possession` records: consecutive events by one team, with a pass count and zone progression, with stopped play excluded.

## Why it comes first

Three of the five signals read possessions rather than raw events. `possession_control` is possession share; `territory` reads zone progression; `pressing_intensity` needs the opponent's pass sequences to count passes per defensive action. Get this wrong and three signals calibrate against noise.

## What to build

- `matchlens/understanding/possession.py`
- `sequence(reader, from_clock_ms, to_clock_ms) -> list[Possession]`, reading events through `RecordReader.events_between`.
- A possession **starts** when the team in control changes, and **ends** on one of the four `PossessionOutcome` values: `shot`, `turnover`, `foul`, `out_of_play`.
- **Events outside `Phase.IN_PLAY` belong to no possession.** The model docstring already says an event may be in none of these, so stopped time is excluded by construction rather than subtracted afterwards.
- `start_zone` and `end_zone` from the first and last in-play event of the possession.
- `pass_count` from the `Action.PASS` events inside it. Whichever rule you pick for incomplete passes, **it must be a pure function of the stored `event_ids`** — the verifier's value check recomputes this number from the citations alone, so a count that depends on anything not in `event_ids` is unverifiable.
- Skip the match events entirely — `substitution`, `red_card`, `yellow_card`, `period_start`, `period_end`, `added_time_announced` carry no positions and are not possession events.
- `calltrace.entered("Understanding")` on the entry point, as `FrameAccess` already does for Ingest.

## Acceptance criteria

- [x] Mean possession length is more than 2 events. A test asserting this catches the "control alternates every event" failure, which is the one that makes possession share meaningless
- [x] No possession spans a stoppage: no `stopped` frame falls between a possession's first and last event. A restart starts the possession it begins (Q10)
- [x] Possessions are in clock order, never overlap, and they cover at least 85% of the match's in-play time, with the ball won back within 3 s of every turnover (Q13)
- [x] **`pass_count` recomputes from `event_ids` alone** and equals the stored value, for every possession in a generated match
- [x] A possession whose last event is a shot has `outcome = shot`, including when that shot is a goal
- [x] `event_ids` is never empty — the model enforces `min_length=1`, so a test that tries to build an empty possession fails at construction
- [x] Same seed, identical possession list, byte for byte

## Definition of done

Criteria pass, `ruff` and `pytest` green, status updated in `docs/BACKLOG.md`.

## Do not

- Do not judge a possession. No "dangerous", no "good build-up", no scoring. That is Spotting, Phase 3, and a detector that decides what matters here is the circularity the design exists to avoid.
- Do not read frames. Possession is event-derived, and `line_height` is the only signal that touches the window.
- Do not emit `SignalReading`. That is U3 and U4.
