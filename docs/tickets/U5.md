# U5 · Epoch detection on goal, red card, half time

**Tier** T1 · **Est** 0.5 day · **Depends on** S2 · **Phase** 2 Understanding

## Goal

Emit an `Epoch` at every structural break, with the score and the player counts **derived from the event log** rather than tracked as state.

## Why it is unblocked now, and was not before

D15 clamps every signal window to the epoch start, so `epoch_id` on a reading is unambiguous and the straddling case that used to make this ticket hard no longer exists.

**D16 is what made it possible at all.** `red_card` and `half_time` were listed as epoch triggers while nothing in the stream emitted them — epoch detection had nothing to detect from. Adding the match events to `Action` fixed that, and `score_state` and `player_counts` now derive from the same log.

## What to build

- `matchlens/understanding/epochs.py`
- `detect(reader) -> list[Epoch]`, a pure function of the event log.
- The **opening epoch** starts at the first `period_start` with `trigger = None`. No other epoch has a null trigger.
- A **new epoch** begins on:
  - any event with `Outcome.GOAL` → `EpochTrigger.GOAL`
  - `Action.RED_CARD` → `EpochTrigger.RED_CARD`
  - the break between periods → `EpochTrigger.HALF_TIME`
- `score_state` and `player_counts` are dicts keyed by team id, **recomputed from the log** at each epoch start (D16). Nothing mutable anywhere.
- Only a red card reduces a player count. A substitution does not. A yellow card is not a break.

## ⚠️ Check this before assuming the generator cooperates

A second yellow is a sending-off in football. If F3's generator does **not** also emit a `red_card` event when it issues a player's second yellow, then a two-yellow dismissal is invisible here: no epoch boundary, and `player_counts` stays at eleven for a ten-man team for the rest of the match.

If that is the case it is **a bug in F3, not something to work around in U5.** Raise it in `docs/QUESTIONS.md` rather than special-casing yellow cards in this module — deriving a dismissal by counting yellows would put roster logic in two places, which is the thing D16 removed.

## Acceptance criteria

- [ ] A match with three goals, one red card and a half-time break produces **six** epochs — the opening one plus five breaks — and the trigger sequence is asserted in order, not just the count
- [ ] `score_state` at each epoch start matches an independent count of goals strictly before that clock
- [ ] `player_counts` drops by one at a red card, and is **unchanged** across a double substitution
- [ ] Epochs are contiguous and non-overlapping: every clock in the match belongs to exactly one
- [ ] The opening epoch's trigger is `None`; every other epoch's is not
- [ ] **Derived, not stored:** running `detect` twice on the same log returns identical rows, and nothing in the module holds score or roster state between calls
- [ ] Two goals at the same clock produce two boundaries or one, deliberately and with a test either way

## Definition of done

Criteria pass, green, status updated.

## Do not

- Do not keep a running score or a roster anywhere. Invariant 2 and D16: anything that looks like mutable state is derived from the log instead.
- Do not treat a substitution, a yellow card or `added_time_announced` as a break.
- Do not read frames.
