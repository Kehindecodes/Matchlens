# A5 walkthrough

**Each model has a breaker on one `Ladder`, kept by the pipeline. One failed moment takes a model down, and two good moments in a row bring it back (Q41).** The rung is A4's prose rung, L0 or L1. A2 is shown beside it as "extra claims on/off". Only Rendering raising takes a moment below L1, and its renditions are then suppressed as `degraded`.

## What had to be decided

- **What can go below L1 (Q41: 1A).** No model failure can, because L7 and L3 use no model. Queue pressure could have blanked cards to catch up, but the brief says never blank a card. That leaves Rendering raising. Before A5, that exception killed the moment's editorial future: no card, no rendition, no audit, a silent hole. Now it is a `degraded` record. L2 and L3 are therefore one runtime state, "could not render". The score and clock come from `MatchState`, which never goes through Rendering.
- **Per card or per match.** A4 already fell back one card at a time. The ladder adds the state between cards, so a dead model is not waited for again on every goal. That is the latency win. While down, A2 no longer holds a goal's card for 15 s.
- **How a down model gets back up.** The options were a timer, a probe call, or asking it as usual and only scoring the answer. A timer means different things at 25× and at 1×. Scoring the normal call costs no extra request, and its answer never reaches a card, so it can never be shown late.
- **A2's "verification failure bar".** It is per moment: more than half of the claims it proposed failed A3. There is no rolling window to reset or size.

## What broke on the way

- **The backlog was always zero.** It counted `_pending`, and `drain()` empties that list. It is now a counter, incremented on submit and decremented in a `finally` after publish.
- **`None` meant two things.** `write` returns `None` for "nothing to word", and a missed deadline also returned `None`. A missed deadline is now `_MISSED`, a `Failure`. `propose` and `write` return a `Failure` instead of `[]` or `None`, so a model that broke can be told apart from one with nothing to add.
- **The rung attribute vanished.** It was set on the moment's parent span, a `NonRecordingSpan`. It now goes on each `rendering` span.
- **`degraded` carried claims.** A `Rendition` validator forbids claims on a suppressed rendition.

## What a reader of this code would get wrong

- **`_score_shadows` waits.** Down-model answers are scored at the start of the next moment, each waited for until its own deadline at most. They are not scored whenever they land. Scoring on arrival races the editorial thread, and a seeded run's cards would then differ between runs (invariant 9). The price: a moment arriving within a deadline of a down model's call can wait out the rest of that deadline.
- **`queue_limit` is None in `run()` and in tests.** An unpaced run queues every moment at once by design. Only the paced feed in `apps/delivery.py` passes `settings.ladder_queue_limit`.
- **The stream sends only changes.** The page reads `GET /ladder` once on load. A stream that opened with the status broke ten stream tests that pin the first event, and the same reasoning already keeps `playback` off a new stream.
- **The switch sits in front of the cache.** Killing the model in the demo also stops cached answers, which is what makes the kill visible at 25×.

## Where the state lives

`Ladder`, one per `Pipeline`, and in `apps/delivery.py` one per process, shared with the HTTP routes. Each breaker holds its up/down state, why it went down, and its run of good answers. **Nothing resets it between matches**, because one pipeline is one match, like `ShownCards`. The editorial thread scores the models, the HTTP thread flips the switch, and the stream reads `version` to send a `ladder` event only when something changed.

## The test that matters

`test_kill_the_model_and_every_card_still_arrives_on_l7s_claims_and_l3s_words`. It runs both models behind a switched-off ladder and requires the cards to be byte-identical to a run with no model at all. If it fails, a model has become a dependency.

## If you change this later

Read D35 first. Never let a model failure set `_unrendered`. Below L1 suppresses cards, and that must only follow from Rendering itself failing.
