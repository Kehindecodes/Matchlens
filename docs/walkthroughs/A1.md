# A1 walkthrough

**The explainer is handed a `FrozenLog`, built from a moment, that holds the events, readings and epochs at or before that moment's clock and nothing else.** `explain()` no longer filters anything. The log is the only place the boundary is drawn.

## What had to be decided

- **Inclusive or strict.** Inclusive: `clock_ms <= moment.clock_ms`. A goal moment's clock is its goal's clock, so a strict log would hide the goal from the moment about it, and the scorer claim would have nothing to cite. A3's temporal check reads "nothing cited from *after* the clock", which says the same. The brief, the backlog row and `ARCHITECTURE.md` now say "at or before". **D19 in `DECISIONS.md` still says `clock_ms < t`** in passing. It is a settled decision, so I left it alone. It needs one word changed, and the change is yours.
- **Where the clock comes from.** The constructor takes a `Moment`, not an `int`, and no read takes a clock. The brief's "do not" is about exactly that kind of hole: a `frozen_log(clock_ms)` would let any caller freeze at full time. A caller can still build a fake moment, but that has to be done on purpose.
- **Snapshot or view.** It copies tuples when it is built and drops the reader. A view over the live `RecordReader` would be cheaper, but then the frozen log would only be as frozen as whatever the record held at the moment you read from it. It would also hold an object that can reach Ingest, and so frames.
- **The clock check in `explain()`.** It is a refusal, not a filter. A log frozen at a later moment would hold that moment's future, so `explain()` raises rather than trusting it. It does not trim anything.

## What broke on the way

Nothing in the explainer. But `test_stage_durations_add_up_to_the_end_to_end_latency` went red on every full-suite run, with ~700 ms outside every span, and passed when run on its own.

- **The cause was a gen-2 collection, not this branch's work.** Timing the GC inside the fixture showed a ~760 ms collection over ~2.5 M live objects, most of them matches that earlier modules cache for the session. A live-object census showed the branch's heap within ~400 objects of the baseline. The extra allocations only moved *when* that collection fired, and it landed in the tracing run. Under parallel load the baseline failed too.
- **The fix is in the fixture:** `gc.collect()` then `gc.freeze()` around `pipeline.run`. The assertion is unchanged. Afterwards, 4 of 5 full runs were green, and I did not capture the name of the test that failed in the fifth. A test that times wall clock will stay sensitive to a busy machine.
- **The `FrozenLog` build moved inside the `explanation` span.** It is Explanation's work, and the old filtering ran inside `explain()`.

## What a reader of this code would get wrong

**`verify(claim, log.events)` is not a second boundary.** Verification gets the frozen events so that A3's temporal check has the same record the explainer had.

## The test that matters

`test_the_explainer_cannot_see_the_future`. Every log in it is built from the *finished* match, so every later event, reading and epoch was in what the log was handed. If the claims come out byte-identical to the live run's, the log served none of it, and `explain()` has no filter left that could have caught it instead. The old version of this test passed a poisoned list straight to `explain()`. It proved only that the list comprehension worked, and deleting that line would have broken invariant 6 with no test going red. I checked it the other way round: make the log serve the whole record and this test fails.

`test_no_attribute_path_reaches_a_frame` walks the object graph. Give `FrozenLog` a `self._record` and it fails.

## If you change this later

A2 must take a `FrozenLog` and nothing wider. Never add an argument to `explain()` that carries events, readings or epochs alongside the log, because that puts back the hole this ticket closed.
