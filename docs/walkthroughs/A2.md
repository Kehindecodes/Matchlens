# A2 walkthrough

**A model is shown a digest of the frozen log and L7's claims, and answers with extra claims in JSON. The answer is parsed into `Claim`s; anything that does not conform gives no claims. The model is asked only after the moment's cards have gone (Q34: A), and what it adds is verified and audited, never shown (Q32: A).**

The tests drive scripted fakes. One live run, `gpt-5.4-mini` over seed 1 on 24 Oct (Q33, later A), is recorded in `docs/evidence/A2-live-seed1.txt` and summarised under **What the live model got wrong** below.

## What had to be decided

- **Who writes the number (Q32, Kehinde: A).** The model writes the whole claim, values and evidence included. The alternative was code computing candidate operands and the model only choosing among them. That would make a wrong number impossible, and with it A3's best demo: rejecting an A2 number while L7's claims stand. The cost of A is that A2's claims are invisible until A3 lands, because `verify()` is still a stub that passes everything.
- **How the hold-out is drawn (Q32 A, then Q34 A).** At first, `explain()` returned L7's and A2's claims together and Selection got `by_rule(claims)`: a filter, one line from being removed. The live run made the call inline untenable (see below). Now the pipeline explains with L7 alone, sends the cards, and only then hands the moment to a one-thread executor that calls `explanation.propose`. The hold-out is no longer a filter but an ordering: by the time the model answers, the cards are already gone. `explain(moment, log, proposer)` still returns both, for callers with no card to send.
- **Whole answer or per claim.** A **shape** failure (it doesn't parse, an invented metric, wrong arity, a self-comparison, a threshold outside the bands, an extra field) throws the **whole** answer away. A model that breaks the format once is not trusted on its other claims, and "partially repaired" is what the brief forbids. A claim citing a row **not in the frozen log** is dropped **on its own** (invariant 5). It is well-formed, it just has nothing to cite.
- **Strict parsing.** `model_validate_json(strict=True)`, so `"0.5"` is not read as `0.5`. Lax mode would quietly repair the answer.
- **What the model is shown.** Shots with their `shot_quality`, possessions from the last ten minutes, the latest reading of each series per epoch, the epochs, and L7's claims. Not the 1,859 raw events: a goal moment needs the goals, not every throw-in.

## What broke on the way

- **The honest fake restated L7.** It compared the fired reading with the opponent's and interpreted the fired reading, which are exactly the two claims L7 already makes. `_restates` dropped both, and the tests saw no interpretive or comparative A2 claims at all. I'd expect a real model to do the same, because the obvious claim is the one the rules already made. That is why the instructions say *"do not repeat a claim already in existing_claims"*, and why the digest includes them.
- **A test's "invented evidence" claim was rejected for the wrong reason.** It copied the first operand, so the gate threw it out as a self-comparison before the citation check ever ran. Shape rules run before citation rules. A test aimed at one rule has to pass all the earlier ones.
- **Cards differed between two runs with the same seed.** The cause was `rendered_at`, which is wall time. The card test now excludes it.
- **The tests started calling the real model.** Once `.env` had an endpoint, every test that goes through `pipeline.run()` built `FoundryProposer`, and the tracing tests sat waiting on Foundry. `tests/conftest.py` now blanks both settings for the whole session. A test that wants a model passes a scripted one.

## What the live model got wrong

There was one run, 52 moments, with 72 claims added: 32 comparative, 30 descriptive, 10 interpretive. Every claim used one of the eight metrics, and none invented a metric or a claim type.

- **24 of 52 calls timed out at 20 s.** This was the biggest failure, and it was latency, not content. The whole run took 741 s. Inline, that meant up to 20 s on every moment's cards, with the replay stalled. That is what Q34 answered: the model now runs off the card path.
- **One answer was thrown away whole,** for an operand with an empty `evidence_ids`. The gate worked as designed: that answer's other claims went with it.
- **5 of 72 claims do not recount from their evidence.** These are the ones A3 should catch:
  - **Wrong counts:** `chances` 6 where the cited shots give fewer, and an opponent's `chances` 1 that does not match its evidence.
  - **A count of nothing:** `goals` 0.0, citing events that are not goals. The instruction is to count goal events. The model claimed a zero and cited something anyway.
  - **Evidence of the wrong kind:** a `possession_control` operand citing an *event* (`m-1-e104`). A signal metric is the value of one reading. The citation check passed, because the event exists, but the evidence does not support the metric.
- **Two moments read one reading at different strengths.** The same `pressing_intensity` reading was interpreted at `+1.25` for one moment and `+2.0` for another. A3's entailment check decides which is right, from the reading's `z_match`.
- **No claim cited a row that is not in the log,** so `_citable` dropped nothing. All the evidence the model invented was real rows cited for the wrong thing.

Nothing the model said reached a card (Q32: A).

## What a reader of this code would get wrong

- **The model's claims are audited separately.** `audit.record` is called twice for a moment with a model: once with L7's claims and the renditions, and once, later, with the model's claims and no renditions. Once Audit stores records (P3), it has to treat them as one moment's trail.
- **`drain()` is what makes a test see the model's claims.** Without it, Audit is read before the model's thread has finished. `run()` drains, and the delivery app instead closes, dropping whatever is still queued, because nobody waits on the model at shutdown.
- **One thread, so a slow model falls behind.** In the live run, the model took about 14 s per moment. At 25× replay, moments arrive faster than that, so the queue grows over the match and the model finishes after the final whistle. Nothing a viewer sees depends on it, but Audit's trail completes late.
- **`_conforms` does not duplicate A3.** It checks shape: same metric, a different subject or window, distinct evidence, a threshold in a band. Whether the numbers or the sign are right is A3's value and entailment work. A model claiming `+2.0` on a reading whose `z_match` is `−2.5` passes A2, and A3 should reject it.

## The test that matters

`test_no_card_depends_on_a2_or_waits_for_it[Liar]`. The model's every number is off by one, and it gives no answer until the test releases it. Every seed-1 card still goes out byte-identical to the no-model run *before* that release. Afterwards, Audit has the model's claims, each with a verification. One test covers D35, Q32 and Q34. Moving the call back inline fails it immediately, because the held model notices being asked on the main thread. I checked that.

## If you change this later

- **When A3 lands:** putting A2's claims on cards means a card waits for the model, or a later card carries them. That is A5's decision now that Q34 has taken the wait away. `Liar`'s test should then show A3 rejecting the claims.
- **When an endpoint exists:** the Dockerfile still leaves the `agents` group out, and `FoundryProposer` will fail to import until it is added. Bump `PROMPT_VERSION` every time the instructions or the digest change (invariant 7).
- **The call still has a timeout** (`explainer_timeout_s`, 20 s), but it holds up only the model's own thread. A timed-out moment just has no model claims.

## D36: on the card path, behind a deadline (25 Oct)

Kehinde took option B: A2's claims go onto cards, replacing Q32: A and Q34: A. The answers to Q37 are a 5 s deadline, later raised to 15 s for v1 and the demo, and goals and chances only.

- **Two threads, and why two.** Model calls go to a pool as soon as a moment fires, so slow calls overlap. The editorial stages (verify, select, render, publish) run on **one** thread, one moment at a time in firing order. Selection's rate limit counts moments in order. A pool there would make which card gets rate-limited depend on which answer came back first, and seeded cards would stop being deterministic.
- **The second release gate is not code.** D1's note asks for release at `max(viewer's due time, deadline)`. A card is published only once its enrichment is settled, and the release queue already releases a late card on arrival. One card per moment and lens, never amended, is what gives D2 identical content.
- **The cache key is the prompt, not the moment.** "Cached claims match the live path" cannot mean the same claims: a real model's output varies. It means the cache answers exactly the prompt the live path would send. A changed digest or prompt version simply misses, and the card ships on L7's claims. Keying on the moment would have served stale answers to a changed prompt and said nothing.
- **What the cache build found.** Under explainer-2, A3 rejected **28 of 49** cached claims, nearly all for one mistake: the model wrote a reading's window itself instead of `[clock − window_ms, clock]`. Writing the window into the digest (explainer-3) took it to **3 of 51** rejected, and those three are genuine (`docs/evidence/A2-cache-seed1.txt`). This is A3 finding the bug, and the fix belongs in the prompt, not the checks.
- **Latency is still not met.** The median is 12 s with reasoning effort low and a prompt a quarter the size. That is service time, not input. At 5 s every live call missed, so the deadline was raised to 15 s for v1 (Q37, amended), which most calls make. Production latency is still to be handled properly. Four calls at a time also hit the deployment's token rate limit, so `explainer_concurrency` is bounded by quota as well as by sense.
- **The test that matters now:** `test_a_model_whose_numbers_are_wrong_changes_no_card`. The liar's every claim fails A3, L7's pass, and every card is byte-identical to the no-model run, on the card path itself. `test_a_model_slower_than_the_deadline_is_not_waited_for` is the other half: a model that never answers costs each moment its deadline, never its card.
