# D1 walkthrough

**Each viewer session holds its own queue of cards and releases them only once that viewer's video has reached the moment they describe.** The open stream pulls from the queue on every tick of the match clock; nothing is pushed from the pipeline side.

## What had to be decided

- **A queue ordered on the clock, or a list scanned for due cards.** The brief warns about the scan, which emits out of order as soon as cards arrive out of clock order. A heap keyed on `(display_at_clock, arrival)` puts the earliest card at the head. Then "release from the head until one is not due" and "release everything due" give the same answer, and order is guaranteed by construction rather than by care. Cost: none worth naming. The arrival counter is there so two cards on the same clock keep the order they came in, and so the heap never has to compare two `Card`s.
- **Pop on release, or keep a log.** Popping is simpler, but a card popped and written to a socket that has just died is gone. Released cards move to a per-session log instead, and a stream sends from the log, not from the release. That is what makes `Last-Event-ID` worth having.
- **What an SSE id means.** SSE gives you one `Last-Event-ID`: the id of whichever event arrived last, a state or a card. If states carry `seq` and cards carry something else, a reconnect knows one of the two and loses the other. So every event carries both, `<seq>:<cards released>`.
- **Where the clock comes from after full time.** The match clock used to arrive only inside a `MatchState`, and the last state is the final whistle. A viewer 45 s behind is still watching, and their last cards would never release. So the hub now holds the clock separately from the state, and the local feed keeps advancing it from the replay's position for as long as the process runs. It is unbounded on purpose: a session that reconnects an hour later is still owed its cards.

## What broke on the way

- **Clamping the viewer's position at zero.** It looked like tidiness, because a negative match clock reads as nonsense. The no-early-release sweep caught it at once: a card at `0:00` was released to a viewer whose video was still showing the pre-match. A negative position is the correct value, so the clamp now applies only to the catch-up call.
- **The old tests released at clock 0.** They passed against the placeholder because it released everything. They now release at the card's own clock.
- **A stray `threading.Timer` in a test.** The resumed card arrived before the timer fired, so the timer published into a server that had already shut down. pytest reported it against the *next* test's teardown.

## What a reader of this code would get wrong

- **`viewer_position` returning a negative number is not a bug.** Clamping it is the bug.
- **The lens check moved into `release_due`.** A card held for a lens the session has since left is popped and not released (L5). It has to happen there, before the log, or the card count in the stream id would include cards the viewer never received.
- **A card that arrives late is released immediately, even if a later card has already gone out.** The queue orders what it holds; it cannot reorder what it has already released. With the in-process pipeline, cards arrive in clock order, so this does not happen today. Over Service Bus (S5) it could.

## Where the state lives

All of it is in-process and lives as long as the delivery process. Like the sessions themselves, it is lost on a restart.

| State | Keyed by | Resets |
|---|---|---|
| pending heap | session id | never; it drains as the viewer's clock passes |
| released log | session id | never; it is the record of what was released |
| `_joined` (catch-up asked) | session id | never, so catch-up runs once per session, not once per connection |
| `sent` cursor | one open stream | per connection: from `Last-Event-ID`, or the end of the log if there is none |
| `last_seen_clock` | the `ViewerSession` | never goes back; replaced on each release |
| hub clock | the process | never goes back (`advance` ignores an earlier clock) |

**The reset that matters is the cursor.** It starts at the end of the log when there is no `Last-Event-ID`, and that is why a reloaded page replays nothing. Start it at zero and every reload replays the whole match's cards. Every test would still pass except the rejoin test.

## The test that matters

`test_no_card_is_ever_released_before_its_clock_less_the_offset`, and its seed-1 version inside `test_seed_one_releases_every_card_never_early_and_the_same_way_twice`. The worst regression is a spoiler: a card about a goal reaching a viewer before their video shows it. That is invariant 8, and it is the one this ticket exists for. The sweep is also what caught the clamp.

## If you change this later

Read invariant 8 and D7 first. **Never compare against wall clock and never anticipate.** If you make the queue smoother, catch a viewer up or fill a gap, it has to be by holding cards back, never by releasing one early. Q29 is still open: the score and clock on the page are not delayed yet.
